# 动作组与标定

## 原始文件

以下文件原样保留：`grab.d6a`（5 帧，约 4.5 秒）、`grab_go_forward.d6a`（10 帧，约 0.95 秒）、`grab_turn_left.d6a`（7 帧，约 1.25 秒）。时间来自 SQLite `ActionGroup.Time` 总和，不包含程序等待和硬件误差。

各文件是 SQLite 数据库。当前每帧含 Index、Time 和 18 个舵机位置列，位置范围 0～1000。官方 TonyPi 1.20 界面图确认1～16是机体舵机；比赛程序保留解析全部列，但只向1～16发送命令。头部1/2为单独的PWM接口，不能把两种编号混淆；原文件17/18列保持原值，不能直接认定为头部控制。详见[官方映射与直接控制说明](../../docs/direct_joint_control.md)。

抓取最后一帧与前进/左转文件中的手臂姿态并不完全相同。比赛程序默认把抓取结束的总线舵机 6/7/8/14/15/16 锁定用于所有抱物步态。要在上位机中确认这些确为本机手臂编号，并实测锁定后步态平衡；若已重新录制整套稳定抱物动作，可以在配置中修改 `hold_arm_servos` 或设为 `[]`。

## 候选文件不是验收后的动作

`candidates/grab_turn_right.d6a`：按标准 TonyPi 对称腿部通道 1↔9、2↔10、3↔11、4↔12、5↔13，以位置互补和为 1000 镜像左转；手臂保持原帧数据。这是运动学候选，未根据你们机器人的机械零位实测。

`candidates/grab_release.d6a`：将抓取帧倒序，帧时间至少 800 ms，作为放下物体的编辑起点。倒放抓取不一定能使物体落到正确位置，需要实测并编辑。

生成工具：

```bash
python3 tools/generate_action_candidates.py --output-dir /tmp/team_action_candidates
```

默认 `candidates` 已有文件，工具拒绝覆盖；生成新版本请选择另一个目录。候选使用 `grab_release` 命名，避免覆盖 Pi 可能已有的出厂 `put_down.d6a`。第四讲课程手册列出了出厂 `put_down`，可以先查看你们 Pi 是否确实存在、是否适合当前自定义抓取结束姿态。

## 上位机验证顺序

1. 在 TonyPi 上位机打开原始 `grab`，把物体放到标定抓取位置。记录最后的双臂位置。
2. 打开候选右转，核对机体舵机编号和零位；首先慢速、单次、空载测试，之后测试抱物转向。观察是否实际右转，不能只看镜像数据就视为正确。
3. 打开放下候选，从真实抱持姿态开始测试，使物体先平稳接近地面，再打开双臂。记录结束姿态。
4. 抓取 → 前进一步 → 左转 → 前进一步 → 右转 → 放下，逐个衔接测试。不要在抱物途中调用普通 `stand`。
5. 测量每个动作的实际距离、角度和可重复性；至少左转、右转各一次，整条路线与障碍有足够余量。
6. 验证后的动作保存到 `humanoid/ActionGroup/calibrated/` 并提交；复制到 Pi 的 `ActionGroups` 中，然后修改比赛配置。候选目录继续保留用于追溯。

README 中的次数是例子，没有测量前不要将 `hardware_calibrated` 设为 true。仅设置该布尔值不会把候选变成可靠动作。
