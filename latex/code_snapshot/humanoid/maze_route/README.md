# maze_route：TonyPi 二维码迷宫路线

让 TonyPi 抱着方块，靠墙上的三张标记码自己走完迷宫：

```
起点 ──直行──▶ A ──左转──▶ 直行 ──▶ B ──右转──▶ 直行 ──▶ C ──停下、放下方块
```

机器人先原地抱起方块，然后朝当前目标码直行，一边走一边把码保持在画面中央。离 A、B 约 40 cm 时转弯，转到看见下一张码再继续走；离 C 约 40 cm 时停下，把方块放到地上。

这是一个**独立的 Python 程序**：在 TonyPi 的树莓派上直接驱动舵机和摄像头，不依赖网页控制台，也不需要 ROS。

> **状态**：识别、测距和路线逻辑已通过离线测试（`tests/test_maze_route.py`）。实机已跑通"抱起 → 走向 A → 在 39.6 cm 处左转"，**完整路线尚未实机验收**。

## 目录内容

```
maze_route/
├── README.md            本文件
├── marker_route.py      主程序：抱起 → 走路线 → 放下，含窗口显示、无头模式和日志
├── markers.py           三张标记码的识别与测距（可单独运行测试图片）
├── robust_camera.py     稳健的 USB 摄像头读取（掉线自动重连）
├── mkcopies.py          在 Pi 上重新生成 actions/ 里的动作副本
└── actions/             程序使用的动作组副本（.d6a）
    ├── grab_final_v2.d6a
    ├── catch_ball_go.d6a
    ├── catch_ball_turn_left.d6a
    ├── catch_ball_turn_right.d6a
    └── put_down.d6a
```

运行时会在本目录下生成 `logs/`（已被 `.gitignore` 忽略）。离线测试在仓库根目录的 `tests/test_maze_route.py`。

### 各文件做什么

| 文件 | 说明 |
|---|---|
| `marker_route.py` | 程序入口。读取摄像头 → 识别目标码 → 决定直行、对中转向、路口转弯或停车 → 播放动作。有桌面时弹出实时窗口，没有时进入无头模式。每次运行都写日志和截图。 |
| `markers.py` | 识别 A、B、C 三张码，用 `solvePnP` 算出到码的距离、码在画面里的方位角，以及机器人相对墙的朝向。`python3 markers.py 图片...` 可以直接检查照片。 |
| `robust_camera.py` | 替代厂家的 `hiwonder.Camera`：按 USB ID 打开摄像头，换了设备编号也能找到；掉线后自动重开；只返回 0.5 s 内的新画面；如果摄像头被网页控制台占着，会请控制台关掉相机。 |
| `mkcopies.py` | 从 Pi 的 `~/TonyPi/ActionGroups/` 读取原始动作，生成 `actions/` 下的副本。原始动作改了以后在 Pi 上重新运行即可。 |
| `actions/*.d6a` | 程序实际播放的动作，见下文"动作"。 |

## 快速开始

在 TonyPi 上（把本目录拷到 Pi，例如 `~/TonyPi/maze/`）：

```bash
cd ~/TonyPi/maze

# 1. 先只看不走：会抬头、识别、在窗口里显示判断结果，但不走路
python3 marker_route.py --dry-run

# 2. 正式运行：窗口里按 S 开始，先抱起，再走路线，最后放下
python3 marker_route.py

# 没有显示器时：3 秒后自动开始，全部过程写进日志
python3 marker_route.py --headless
```

窗口按键：

| 键 | 作用 |
|---|---|
| **S** | 开始 / 暂停后继续 |
| **P** | 做完当前动作后暂停 |
| **Q** / Esc | 退出 |
| **[** / **]** | 头部俯仰 −20 / +20（仅在未运行时） |

**注意**：启动时程序会关闭占用舵机串口的厂家上位机，并停止 `tonypi.service`（手机 App 和厂家 RPC 会暂时不可用）。用完后如需恢复：`sudo systemctl start tonypi`。第一次实跑请在旁边扶着机器人。

## 工作流程

1. **准备**：关闭占用串口的程序 → 头部设到中立位（俯仰 1500、左右 1482），之后全程不动 → 打开摄像头。
2. **抱起**：原地播放 `grab_final_v2`，然后把手臂锁定在抱物姿态。
3. **走向目标码**：每次判断前取连续 3 帧，结果取中位数。
   - 码偏离画面中心较多 → 转一次（`catch_ball_turn_left/right`）把它拉回中央。
   - 码在中央附近 → 直行一步（`catch_ball_go`），然后停 200 ms。
   - 暂时看不到码 → 按学到的每步偏航补偿方向，继续直行。
4. **路口（A、B）**：距离 ≤ 40 cm 时开始转弯：停 300 ms → 转一次 → 停 300 ms → 看一眼，重复直到看到下一张码，再回到第 3 步。
5. **终点（C）**：距离 ≤ 40 cm 时停下，停 300 ms 后播放 `put_down` 放下方块，结束。

### 为什么这样设计

- **对中不会来回摆**：`catch_ball_turn` 一次转约 30°，偏差太小时转一下只会转到另一边。程序会在运行中测量单次转角，只有偏差超过它的 60% 才转。
- **会自己学走偏**：抱物直行每步都会往一侧偏（实测左偏约 10–15°/步）。程序从看得到码时的读数里学出这个偏航，在看不到码时用它补偿。
- **太近时码会出画面**：头部在中立位时，离墙约 37 cm 以内码会从画面下沿移出。所以停车距离默认 40 cm；如果码正好在目标附近、居中时丢失，也按"已到达"处理。
- **出问题不乱走**：连续 20 步几乎没靠近目标、路口转满一圈找不到下一张码、摄像头 60 s 没画面，都会停下。有窗口时暂停等你按 S，无头模式直接结束。摄像头短暂掉线时原地等待恢复。

## 动作

只使用队伍指定的基础动作。副本的帧数、每帧时长、腿部数值都和原动作一致，只改手臂：

| 用途 | 文件 | 相对原动作的改动 |
|---|---|---|
| 抱起 | `grab_final_v2.d6a` | 无，原样复制 |
| 直行一步 | `catch_ball_go.d6a` | 手臂 6/7/8/14/15/16 改为 `grab_final_v2` 最后一帧（566/908/40/435/108/935） |
| 转弯、对中 | `catch_ball_turn_left.d6a`、`catch_ball_turn_right.d6a` | 同上 |
| 放下 | `put_down.d6a`（官方原装） | 只把第一帧（下蹲）的手臂改为抱紧姿态，防止下蹲时方块滑落 |

播放时手臂始终锁定在抱物姿态（放下动作除外）。如果某个动作的第一帧和当前姿态相差超过 25，程序会把这一帧拉长到 300 ms 做平滑过渡。

## 常用参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--no-grab` | | 跳过开头的抱起（已经抱着方块时用） |
| `--no-release` | | 到 C 后不放下方块 |
| `--dry-run` | | 只识别和判断，不走不转（仍会设置头部） |
| `--no-servos` | | 完全不碰舵机串口（隐含 `--dry-run`） |
| `--headless` | | 不弹窗口，`--start-delay`（3 s）后自动开始 |
| `--turn-cm` | 40 | 离 A、B 多近开始转弯 |
| `--stop-cm` | 40 | 离 C 多近停下 |
| `--head-pitch` / `--head-pan` | 1500 / 1482 | 头部 PWM 舵机位置，全程固定 |
| `--turn-step-deg` | 20 | 单次转角的初始猜测，运行中会被实测值取代 |
| `--centre-deg` | 8 | 偏差小于这个角度从不转向 |
| `--max-corner-turns` | 12 | 路口最多转几次还找不到就停（约一圈） |
| `--stall-steps` / `--stall-cm` | 20 / 5 | 连续这么多步距离缩短不到这么多就停 |
| `--camera-wait` | 60 | 摄像头掉线最多等几秒 |

完整列表：`python3 marker_route.py --help`。

## 日志

每次运行生成 `logs/route-<时间>/`，无头模式也一样：

| 文件 | 内容 |
|---|---|
| `route.log` | 启动参数、头部设置、摄像头掉线与恢复、每段开始、转角测量、暂停原因、结束状态 |
| `decisions.csv` | 每次判断一行：时间、阶段、目标码、看了几帧/看到几次、距离、方位角、朝向、采取的动作和原因 |
| `snapshots/` | 每次判断时的标注截图（最多 500 张） |

排查问题时先看 `decisions.csv`：能看出每一步是直行、对中还是转弯，以及当时离码多远、偏了多少。

## 标记码与标定

- **三张码不是 OpenCV 自带的 ArUco/AprilTag 字典**，要用本目录的 `markers.py` 识别。每张码是 9×9 格：外圈 2 格黑边，中间 5×5 数据；黑色正方形边长 **14 cm**。三张码的模板在 `markers.py` 的 `TEMPLATES` 里，任意旋转下至少相差 4 格，识别时允许读错 1 格。
- **对应关系**：A 是第一段终点（到了左转），B 是第二段终点（到了右转），C 是终点（停下放下）。
- **距离**是摄像头到码中心的直线距离。码中心比摄像头低约 13 cm，所以水平 40 cm 时读数约 42 cm。
- **相机内参**读取 Pi 上的 `~/TonyPi/Functions/CameraCalibration/calibration_param.npz`。
- **精度**（离线合成图）：30–60 cm 测距误差约 1–2 cm，朝向误差 ±2°；实机在 194 cm 处已能识别。

## 已知问题

- **走得慢**：抱物直行每步只前进约 3.4 cm，且明显左偏，一半以上的动作在纠偏，全程预计 5–7 分钟。把抱物步态调直是最有效的改进。
- **摄像头会掉线**：转身等舵机大负载时，USB 摄像头会断开几秒，可能是供电跌落。程序会原地等待，但建议固定好线缆、检查电量。
- **C 可能太远**：C 离 B 转弯点约 2.2–2.6 m，可能超出识别距离。如果右转后转满一圈仍看不到 C，可以把码打印得更大。
